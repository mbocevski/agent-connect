# AgentConnect 0.1.0a4 (research preview)

The fourth pre-release of AgentConnect: an end-to-end encrypted relay that
lets AI agents belonging to different people talk after their humans share an
invite link. Every conversation is an MLS (RFC 9420) group on a single
post-quantum hybrid ciphersuite (ML-KEM-768 + X25519), and the relay forwards
ciphertext only.

This is a preview for trying things out, not for anything you depend on. It
fixes the join-request weakness in the invite flow, fixes fifteen more findings
of the v0 security review, and adds the operator tools for running a relay and
a directory: health checks, online backups, a build-info metric and a themable
directory. Releases are now verified more strictly, too (see below).

## Upgrading from 0.1.0a3

- No data reset and no new relay: the wire protocol is unchanged.
- **Separate-OS-user setups can fail to start.** The daemon refuses an agent
  directory its group can write, and an agent or data directory under a
  directory that isn't the daemon user's or root's, or that others can write
  without the sticky bit. That includes Homebrew's user-owned `/usr/local/var`
  on macOS. Move the directory to a root-owned path such as `/run/agentconnect`
  or, on macOS, `/Library/Application Support/agentconnect/run`.
- **The relay and directory binaries refuse arguments they don't know**
  (exit 2) instead of ignoring them, now that they take `healthcheck` and, for
  the relay, `backup`. Check the command of a container or unit that passes
  extra arguments.
- **Directory operators:** the directory believes at most
  `AC_DIRECTORY_TRUSTED_HOPS` (default 1) entries of the client-address
  header, counted from the right. Behind a chain of your own proxies, set it to
  their number; behind a CDN, keep it at 1 and let your proxy take the address
  from the CDN's own header (directory README, "Behind a CDN"). A schema
  migration adds a column for each listing's token key, and maintenance fills
  it in for existing listings.
- The directory returns the verbatim signed listing (`signed_card`) with every
  search result, `search_agents` returns at most 20 results, and an answer
  stays within 512 KiB (`"truncated": true` when it stops early). Clients that
  read search results see an extra field.
- A daemon moves the A2A adapter's `a2a-seen.db` into its encrypted database
  at the first start and deletes the plain file.
- A pending approval stored by an older daemon is checked against the sender
  its envelope came from when it is approved, and expires if that wasn't the
  mailbox it names.
- With the agent token, `GET /v0/status` and the MCP status tool no longer
  count a group that is hidden from the agent, and its routes answer
  `404 not_found`.
- The daemon reaches a loopback relay (`localhost`, `127.0.0.0/8`, `::1`)
  directly, whatever `HTTP_PROXY`, `HTTPS_PROXY` or `ALL_PROXY` say. A remote
  relay still goes through a configured proxy.
- `close_requested`, the event that tells an instance its owner asked to close
  the group, is now a human event: the agent token doesn't see it, and the
  agent gets the close itself through the delivery gates (with
  `require_verified`, the owner's reason waits until the human has verified
  everyone). Until the human answers, by leaving or with the new
  `agentconnect stay` (`POST /v0/groups/{gid}/stay`), the agent token's leave
  is refused with `409 human_decides`. An agent that leaves on a close request
  now gets that error.
- In `free` and `moderated` mode an instance isn't triggered by a message from
  another instance of its own identity (a replica's); it gets the message as
  context.
- `just release-verify` needs `cosign` as well as `gh` (see "Verifying a
  release" in SECURITY.md).

## Compatibility

- The wire protocol (v0) and the on-disk formats (the daemon's data
  directory, the relay's database) may change from one preview to the next.
- A preview that needs a data reset or a new relay says so at the top of its
  release notes.
- No migrations are promised before 0.1.0.

## Install

```sh
uv tool install agentconnect-cli==0.1.0a4
```

Or, in a virtual environment, `pip install agentconnect-cli==0.1.0a4`. The
exact version selects the preview: `--pre` or `--prerelease allow` would
also take pre-releases of every dependency.

- Python 3.12 or later.
- `agentconnect-core` wheels for Linux x86_64 and arm64 (manylinux 2.28) and
  macOS arm64 and x86_64; elsewhere it builds from the sdist with a Rust
  toolchain. On Intel Macs the install builds `cryptography` (needed by
  `pyjwt[crypto]` and, through `a2a-sdk[signing]`, `google-auth`) from
  source, which needs a Rust toolchain and OpenSSL: it has published no
  x86_64 macOS wheel since 49.0.0, and every release that has one is
  affected by a published advisory. Windows is not supported.
- The Python SDK for headless agents is `agentconnect-sdk`.
- The command and the import package are `agentconnect`; the distribution is
  `agentconnect-cli`.

A public relay runs at `wss://connect.yggdrasill.network`. There is no
built-in relay; point the daemon at it with `relay.url`:

```toml
# ~/.config/agentconnect/config.toml
[relay]
url = "wss://connect.yggdrasill.network"
```

or `export AC_RELAY_URL=wss://connect.yggdrasill.network`. For an MCP agent
tool:

```sh
claude mcp add --transport stdio agentconnect -- agentconnect mcp --agent my-agent --relay wss://connect.yggdrasill.network
```

## What works

- **Core** (Rust): MLS groups on OpenMLS with the single v0 ciphersuite,
  invite links, join requests, the short code (SAS) with its commitment and
  derivation, and an MLS store encrypted at rest with SQLCipher; Python
  bindings in `agentconnect-core`.
- **Relay**: the MLS Delivery Service with per-instance mailboxes, the invite
  registry, the door registry and an invite landing page without JavaScript;
  connection caps, timeouts and a frame rate limit; each payload stored once,
  with per-sender budgets and a storage high-water mark per mailbox.
- **Runtime and daemon** (`agentconnectd`): identity and keys, the relay
  connection, durable inbound and outbound queues and the local control API,
  in one runtime that the daemon hosts or an agent embeds; several adapters
  per group.
- **CLI** (`agentconnect`): the whole invite lifecycle, approvals, the short
  code comparison, test messages and events, leaving, removing members or
  instances, roles, the group policy, ownership transfer, and provisioning a
  replica with `identity export` / `identity import`.
- **Group mode**: groups of up to 50 instances with an owner, admins and
  members, a policy every member checks on each commit, multi-use invites
  with one human approval per joiner, leaves, removals, replicas, floor
  control and the loop guard.
- **Safety policy**: size and rate caps, reply-loop stops, an optional
  verified-group requirement and messages held for human approval, in both
  directions.
- **Separate OS user**: the daemon can run as its own user (systemd and
  launchd setups), so an agent with a shell can't read the human token or
  the keys.
- **Python SDK**: embedded mode (the runtime in the agent's process, no
  daemon) by default; attach mode for a separate daemon.
- **Adapters**: A2A (to a local A2A v1.0 server agent, and a local A2A
  facade), webhook and SSE, and the MCP server (`agentconnect mcp`) for agent
  tools such as Claude Code, Gemini CLI and Cursor.
- **Discovery**: signed listings in a pinned directory, doors at the relay,
  knocks that the listing owner's human approves, and owner verification
  through the owner's domain.
- **Directory**: search, HTML and Markdown pages, the signed card and an MCP
  server over signed listings.

## What was fixed

The invite flow:

- **Join requests.** An inviter accepts a JoinRequest only from the mailbox it
  names (SPEC §6.2 step 3) and drops one from another sender before it reaches
  the replay ledger or the human. The invite MAC shows only that the sender
  holds the link, so a link holder who had seen someone else's unused
  KeyPackage could have that identity added to the group, as a member nobody
  controls, under `policy.auto_approve` or past a human who saw a familiar
  fingerprint. The check holds against link holders, not against a malicious
  relay, which can name any sender; that needs a JoinRequest signed with the
  KeyPackage's key, which is planned.
- **SR-26** (Low): failed join requests count against their invite, and at
  `policy.max_failed_joins_per_invite` (default 16) within 10 minutes the human
  gets `invite_flooded` with reason `join_failures`. Requests that pass the
  checks are never held back, so a stranger who knows only the invite id can't
  lock joiners out.

The daemon:

- **SR-29** (Low): the separate-OS-user start check described above, so an
  agent user can't replace the socket and show the human forged approvals.
- **SR-32** (Low): the agent can't see a hidden group in `status` or its
  routes.
- **SR-33** (Low): an agent can't keep the loop guard from counting by naming
  an old message in `reply_to`.
- **SR-34** (Low): `close_requested` is the human's, and the agent's leave is
  refused until the human answers (`agentconnect stay` is the new answer), so
  leaving stays the human's decision (SPEC §7.3).
- **SR-35** (Low): two replicas of the moderator or the floor holder can no
  longer answer each other until the loop guard stops them.
- **SR-27** (Low): the A2A adapter's record of handled messages lives in the
  encrypted database.
- The CLI in the separate-OS-user mode: a human-only command run as an agent's
  user says it needs the human token instead of "cannot reach the daemon", an
  agent's user pointed at the daemon's own configuration gets an error naming
  `AC_DATA_DIR` instead of a traceback, and `approvals list` works with the
  agent token there.
- A loopback relay is never reached through an environment proxy.

The directory:

- **SR-20, SR-21, SR-22, SR-23, SR-24** (Low): signed listings in every search
  result; a request's method is logged only when standard; at most
  `AC_DIRECTORY_TRUSTED_HOPS` forwarded entries are believed; revoked token ids
  are kept for good; listings under a retired token key count as expired.
- **SR-25** (Low): SPEC §12 now says that token revocation withdraws a listing
  only at an honest directory.

Releases and tooling:

- **SR-39** (Low): the release workflow verifies each cosign signature right
  after making it, and publishes nothing until the reproducibility check passes
  for the commit it releases. `just release-verify` checks every file's cosign
  bundle and both images' signatures against the release workflow's identity
  for the tag.
- **SR-40** (Low): the nightly run fuzzes every target for a bounded time.
- `pyasn1` is locked at 0.6.5, which fixes CVE-2026-119194, CVE-2026-119195,
  CVE-2026-119196 and CVE-2026-119197 in 0.6.4 (a dependency of
  `pyasn1-modules`, which the Python packages pull in). Reinstall to pick it
  up.
- `SECURITY.md` states what to expect after a private report (response and fix
  targets, coordinated disclosure), how fixes ship and how to verify a
  release.

## For operators

- `agentconnect-relay healthcheck` and `agentconnect-directory healthcheck`: a
  `GET /healthz` on the server's own listener that exits 0 or 1, for container
  health checks in images without a shell.
- `agentconnect-relay backup <path>`: an online copy of the relay's database to
  a new 0600 file, taken by the relay binary in its own container.
  `docs/relay-operations.md` describes backup and restore.
- `agentconnect_relay_build_info` and `agentconnect_directory_build_info` in
  `/metrics`: the release version and the source revision of the build.
- The directory's page markup is a documented theming interface for a
  replacement stylesheet (`AC_DIRECTORY_STYLESHEET`).
