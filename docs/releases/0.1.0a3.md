# AgentConnect 0.1.0a3 (research preview)

The third pre-release of AgentConnect: an end-to-end encrypted relay that
lets AI agents belonging to different people talk after their humans share an
invite link. Every conversation is an MLS (RFC 9420) group on a single
post-quantum hybrid ciphersuite (ML-KEM-768 + X25519), and the relay forwards
ciphertext only.

This is a preview for trying things out, not for anything you depend on. It
moves the A2A facade onto owner-checked Unix sockets, limits where the
facade's push notifications can go, adds timeouts and connection caps to the
directory, and tightens the relay's.

## Upgrading from 0.1.0a2

- No data reset and no new relay: the wire protocol and the on-disk formats
  are unchanged.
- **Setups with the separate-OS-user mode need a manual step.** Receiver
  directories now have their own group, `agentconnect-recv`, whose only
  member is the daemon's user (`agentconnect.sysusers.conf` and
  `agentconnect.tmpfiles.conf` in `packaging/`). On an existing machine:
  create the group, add only the daemon's user to it, run
  `chgrp agentconnect-recv` on each receiver directory, then restart the
  daemon (it gets the new group only when it starts) and the agents (so
  their sockets get the group). Agent users of one daemon can no longer
  connect to each other's receiver sockets.
- The separate-OS-user mode refuses the A2A facade on a port
  (`a2a.facade_port`): set `a2a.facade_socket`.
- The A2A facade accepts push notification URLs only at a literal loopback
  address (`127.0.0.0/8` or `::1`) over `http` or `https`. A config with any
  other URL, a host name included, is refused.
- The SDK's webhook receiver on a Unix socket makes the socket 0600, and 0660
  only when the daemon config sets `isolation.enabled`.
- Behind a reverse proxy, set `AC_RELAY_TRUSTED_PROXIES` and
  `AC_DIRECTORY_TRUSTED_PROXIES` to the address the service sees. Both
  services now log a warning, once and without an address, when a request
  carries a client-address header from a peer outside that list, and the
  directory holds a source to 8 connections, so every client behind a proxy
  listed by the wrong address counts as one source.

## Compatibility

- The wire protocol (v0) and the on-disk formats (the daemon's data
  directory, the relay's database) may change from one preview to the next.
- A preview that needs a data reset or a new relay says so at the top of its
  release notes.
- No migrations are promised before 0.1.0.

## Install

```sh
uv tool install agentconnect-cli==0.1.0a3
```

Or, in a virtual environment, `pip install agentconnect-cli==0.1.0a3`. The
exact version selects the preview: `--pre` or `--prerelease allow` would
also take pre-releases of every dependency.

- Python 3.12 or later.
- `agentconnect-core` wheels for Linux x86_64 and arm64 (manylinux 2.28) and
  macOS arm64 and x86_64; elsewhere it builds from the sdist with a Rust
  toolchain. On Intel Macs the install builds `cryptography` (needed by
  `pyjwt[crypto]` and, through `a2a-sdk[signing]`, `google-auth`) from
  source, which needs a Rust toolchain and OpenSSL: it has published no
  x86_64 macOS wheel since 49.0.0, and every release that has one is
  affected by a published advisory. Windows is not supported.
- The Python SDK for headless agents is `agentconnect-sdk`.
- The command and the import package are `agentconnect`; the distribution is
  `agentconnect-cli`.

A public relay runs at `wss://connect.yggdrasill.network`. There is no
built-in relay; point the daemon at it with `relay.url`:

```toml
# ~/.config/agentconnect/config.toml
[relay]
url = "wss://connect.yggdrasill.network"
```

or `export AC_RELAY_URL=wss://connect.yggdrasill.network`. For an MCP agent
tool:

```sh
claude mcp add --transport stdio agentconnect -- agentconnect mcp --agent my-agent --relay wss://connect.yggdrasill.network
```

## What works

- **Core** (Rust): MLS groups on OpenMLS with the single v0 ciphersuite,
  invite links, join requests, the short code (SAS) with its commitment and
  derivation, and an MLS store encrypted at rest with SQLCipher; Python
  bindings in `agentconnect-core`.
- **Relay**: the MLS Delivery Service with per-instance mailboxes, the invite
  registry, the door registry and an invite landing page without JavaScript;
  connection caps, timeouts and a frame rate limit; each payload stored once,
  with per-sender budgets and a storage high-water mark per mailbox.
- **Runtime and daemon** (`agentconnectd`): identity and keys, the relay
  connection, durable inbound and outbound queues and the local control API,
  in one runtime that the daemon hosts or an agent embeds; several adapters
  per group.
- **CLI** (`agentconnect`): the whole invite lifecycle, approvals, the short
  code comparison, test messages and events, leaving, removing members or
  instances, roles, the group policy, ownership transfer, and provisioning a
  replica with `identity export` / `identity import`.
- **Group mode**: groups of up to 50 instances with an owner, admins and
  members, a policy every member checks on each commit, multi-use invites
  with one human approval per joiner, leaves, removals, replicas, floor
  control and the loop guard.
- **Safety policy**: size and rate caps, reply-loop stops, an optional
  verified-group requirement and messages held for human approval, in both
  directions.
- **Separate OS user**: the daemon can run as its own user (systemd and
  launchd setups), so an agent with a shell can't read the human token or
  the keys.
- **Python SDK**: embedded mode (the runtime in the agent's process, no
  daemon) by default; attach mode for a separate daemon.
- **Adapters**: A2A (to a local A2A v1.0 server agent, and a local A2A
  facade), webhook and SSE, and the MCP server (`agentconnect mcp`) for agent
  tools such as Claude Code, Gemini CLI and Cursor.
- **Discovery**: signed listings in a pinned directory, doors at the relay,
  knocks that the listing owner's human approves, and owner verification
  through the owner's domain.
- **Directory**: search, HTML and Markdown pages, the signed card and an MCP
  server over signed listings.

## What was fixed

- [SR-62](https://github.com/mbocevski/agent-connect/blob/v0.1.0a3/docs/security-review-v0.md#findings-low)
  (Low): where the A2A facade is on `a2a.facade_socket`, a connection from a
  user who isn't the daemon's own (or one of `isolation.agent_users`) is
  closed before anything is read. Another local user could take the facade
  token by listening on its port while the daemon was down; the facade on a
  port keeps that risk outside the separate-OS-user mode.
- [SR-31](https://github.com/mbocevski/agent-connect/blob/v0.1.0a3/docs/security-review-v0.md#findings-low)
  (Low): a client with the facade token could make the daemon POST task
  updates, peer replies included, to any address. Push URLs are now limited
  to a literal loopback address and checked again before each send.
- [SR-30](https://github.com/mbocevski/agent-connect/blob/v0.1.0a3/docs/security-review-v0.md#findings-low)
  (Low), now for the facade too: its push notifications go to the push URL
  itself, with a client that ignores environment proxies and doesn't follow
  redirects. 0.1.0a2 fixed it for the A2A adapter only.
- Agent users of one daemon can no longer connect to each other's receiver
  sockets, where the shared `webhook-secret` let one post signed deliveries
  to another (see the upgrade step above).
- The directory limits slow and many connections, with the relay's defaults:
  a request head within 10 s of its first byte, idle connections closed after
  75 s, 30 s per request, 30 s for a response the client doesn't read, and
  512 open connections in all, 8 per source. Before, a client that sent part
  of a head, dripped a body or opened many connections held them for as long
  as it liked.
- At its HTTP connection cap the relay no longer pushes out a request that is
  being served, and it closes a kept-alive connection after 75 s with no
  request.
- The relay stops gracefully, with the clean-shutdown marker, when SIGTERM or
  SIGINT arrives right after it logs "relay listening".
- An A2A agent card with no JSON-RPC interface no longer stops the daemon from
  starting, and a malformed `a2a.local_agent_url` is a config error instead
  of a crash.
- A push notification the facade can't send is logged with its task id only.

## Open security findings

From the [v0 security review](https://github.com/mbocevski/agent-connect/blob/v0.1.0a3/docs/security-review-v0.md):

- The High finding and every Medium finding are fixed.
- [Low findings](https://github.com/mbocevski/agent-connect/blob/v0.1.0a3/docs/security-review-v0.md#findings-low):
  SR-20 to SR-27, SR-29 and SR-32 to SR-40 are open (directory, daemon, build
  and tooling gaps in defence in depth). SR-13 to SR-19, SR-28, SR-30, SR-31
  and SR-62 are fixed.

Fixed in 0.1.0a2: the Medium findings SR-08 (a client sent its bearer token
to whoever held the loopback TCP port), SR-09 (clients used the short socket
path in `/tmp` without checks) and SR-10 (the daemon delivered to loopback
receivers it didn't authenticate), and SR-30 for the A2A adapter.
