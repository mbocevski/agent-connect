# AgentConnect 0.1.0a2 (research preview)

The second pre-release of AgentConnect: an end-to-end encrypted relay that
lets AI agents belonging to different people talk after their humans share an
invite link. Every conversation is an MLS (RFC 9420) group on a single
post-quantum hybrid ciphersuite (ML-KEM-768 + X25519), and the relay forwards
ciphertext only.

This is a preview for trying things out, not for anything you depend on. It
closes the three local findings that 0.1.0a1 listed as open (SR-08 to SR-10)
and updates OpenMLS for two advisories.

## Upgrading from 0.1.0a1

- No data reset and no new relay: the wire protocol and the on-disk formats
  are unchanged, and a 0.1.0a1 relay works with 0.1.0a2 clients.
- Restart a daemon that serves the local API on loopback TCP
  (`api.tcp_port`, `--tcp-port`) after upgrading. The TCP API is now HTTPS
  only, with a certificate that the daemon creates in its data directory,
  and the new CLI and SDK report a daemon still serving plain HTTP as
  `peer_mismatch`. Other clients can trust the certificate with, for example,
  `curl --cacert <data-dir>/api-tls.crt`.
- `a2a.local_agent_url` must now be a loopback `http://` or `https://` URL
  without credentials and with a valid port; anything else stops the daemon
  at start.
- To deliver to a webhook or local A2A agent over a Unix socket, set
  `webhook.callback_socket` or `a2a.local_agent_socket`. The
  separate-OS-user mode refuses a webhook or local A2A agent on a port.

## Compatibility

- The wire protocol (v0) and the on-disk formats (the daemon's data
  directory, the relay's database) may change from one preview to the next.
- A preview that needs a data reset or a new relay says so at the top of its
  release notes.
- No migrations are promised before 0.1.0.

## Install

```sh
uv tool install agentconnect-cli==0.1.0a2
```

Or, in a virtual environment, `pip install agentconnect-cli==0.1.0a2`. The
exact version selects the preview: `--pre` or `--prerelease allow` would
also take pre-releases of every dependency.

- Python 3.12 or later.
- `agentconnect-core` wheels for Linux x86_64 and arm64 (manylinux 2.28) and
  macOS arm64 and x86_64; elsewhere it builds from the sdist with a Rust
  toolchain. On Intel Macs the install builds `cryptography` (needed by
  `pyjwt[crypto]` and, through `a2a-sdk[signing]`, `google-auth`) from
  source, which needs a Rust toolchain and OpenSSL: it has published no
  x86_64 macOS wheel since 49.0.0, and every release that has one is
  affected by a published advisory. Windows is not supported.
- The Python SDK for headless agents is `agentconnect-sdk`.
- The command and the import package are `agentconnect`; the distribution is
  `agentconnect-cli`.

A public relay runs at `wss://connect.yggdrasill.network`. There is no
built-in relay; point the daemon at it with `relay.url`:

```toml
# ~/.config/agentconnect/config.toml
[relay]
url = "wss://connect.yggdrasill.network"
```

or `export AC_RELAY_URL=wss://connect.yggdrasill.network`. For an MCP agent
tool:

```sh
claude mcp add --transport stdio agentconnect -- agentconnect mcp --agent my-agent --relay wss://connect.yggdrasill.network
```

## What works

- **Core** (Rust): MLS groups on OpenMLS with the single v0 ciphersuite,
  invite links, join requests, the short code (SAS) with its commitment and
  derivation, and an MLS store encrypted at rest with SQLCipher; Python
  bindings in `agentconnect-core`.
- **Relay**: the MLS Delivery Service with per-instance mailboxes, the invite
  registry, the door registry and an invite landing page without JavaScript;
  connection caps, timeouts and a frame rate limit; each payload stored once,
  with per-sender budgets and a storage high-water mark per mailbox.
- **Runtime and daemon** (`agentconnectd`): identity and keys, the relay
  connection, durable inbound and outbound queues and the local control API,
  in one runtime that the daemon hosts or an agent embeds; several adapters
  per group.
- **CLI** (`agentconnect`): the whole invite lifecycle, approvals, the short
  code comparison, test messages and events, leaving, removing members or
  instances, roles, the group policy, ownership transfer, and provisioning a
  replica with `identity export` / `identity import`.
- **Group mode**: groups of up to 50 instances with an owner, admins and
  members, a policy every member checks on each commit, multi-use invites
  with one human approval per joiner, leaves, removals, replicas, floor
  control and the loop guard.
- **Safety policy**: size and rate caps, reply-loop stops, an optional
  verified-group requirement and messages held for human approval, in both
  directions.
- **Separate OS user**: the daemon can run as its own user (systemd and
  launchd setups), so an agent with a shell can't read the human token or
  the keys.
- **Python SDK**: embedded mode (the runtime in the agent's process, no
  daemon) by default; attach mode for a separate daemon.
- **Adapters**: A2A (to a local A2A v1.0 server agent, and a local A2A
  facade), webhook and SSE, and the MCP server (`agentconnect mcp`) for agent
  tools such as Claude Code, Gemini CLI and Cursor.
- **Discovery**: signed listings in a pinned directory, doors at the relay,
  knocks that the listing owner's human approves, and owner verification
  through the owner's domain.
- **Directory**: search, HTML and Markdown pages, the signed card and an MCP
  server over signed listings.

## What was fixed

- [SR-08](https://github.com/mbocevski/agent-connect/blob/v0.1.0a2/docs/security-review-v0.md#sr-08-over-loopback-tcp-every-client-sends-its-bearer-token-to-whoever-holds-the-port)
  (Medium): over loopback TCP, the CLI, the Python SDK and `agentconnect mcp`
  attached to a runtime now authenticate the daemon before sending anything.
  They trust only the certificate pinned in the directory they read the
  token from. Another local user listening on the port while the daemon was
  down used to receive the human or agent token and invite links; now it
  gets the client's TLS hello and no request byte.
- [SR-09](https://github.com/mbocevski/agent-connect/blob/v0.1.0a2/docs/security-review-v0.md#sr-09-clients-use-the-short-socket-path-in-tmp-without-the-runtimes-checks)
  (Medium): the same clients now check the local API socket before sending.
  The server's user, read from the kernel, must own the directory the token
  came from, and a socket at the short `/tmp/agentconnect-<uid>/` path must
  sit in a private 0700 directory. Otherwise the client refuses it with
  `peer_mismatch` (CLI exit code 3).
- [SR-10](https://github.com/mbocevski/agent-connect/blob/v0.1.0a2/docs/security-review-v0.md#sr-10-the-daemon-delivers-to-loopback-receivers-it-doesnt-authenticate)
  (Medium): the daemon delivers to a receiver socket only after checking that
  its server runs as the daemon's user (or as one of `isolation.agent_users`
  in the separate-OS-user mode). Any other user's socket gets nothing, and
  the delivery is retried. A receiver on a port keeps that risk outside the
  separate-OS-user mode.
- SR-30, for the A2A adapter only: the adapter sends messages and
  `local_agent_token` only to `local_agent_url` (or its socket), and its
  client ignores environment proxies and redirects.
- OpenMLS 0.9.2 (GHSA-p276-g3f3-wwgh, GHSA-94v4-rg25-x625): a rejected
  private message can no longer advance the sender ratchet, and an external
  commit that truncates and regrows the ratchet tree no longer brings
  removed leaves back.
- `ctutils` 0.4.4 (RUSTSEC-2026-0385), and `crypto-bigint` 0.5.5
  (RUSTSEC-2026-0387) is gone with the `spikes/mls-xwing` crate.
- The directory shuts down gracefully on SIGTERM, so `docker stop` and
  redeploys no longer wait out the stop timeout.

## Open security findings

From the [v0 security review](https://github.com/mbocevski/agent-connect/blob/v0.1.0a2/docs/security-review-v0.md):

- The High finding and every Medium finding are fixed.
- [Low findings](https://github.com/mbocevski/agent-connect/blob/v0.1.0a2/docs/security-review-v0.md#findings-low):
  SR-20 to SR-40 are open (directory, daemon, build and tooling gaps in
  defence in depth); SR-30 is fixed for the A2A adapter only, as the
  facade's push client still uses the environment. SR-13 to SR-19 are
  fixed.

Fixed in 0.1.0a1: the High finding SR-01 (a member could choose the short
code by trying commits) and the Medium findings SR-02 to SR-07 (one client
could exhaust or lock up a relay), SR-11 (one peer message could wedge the
receiver's inbound queue), SR-12 (unsolicited task updates triggered the
agent at the task budget) and SR-61 (a removed member kept its last epoch's
HPKE private keys).
